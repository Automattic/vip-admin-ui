# Strings and translation

## TL;DR

| | |
| --- | --- |
| The package ships | No translatable strings. None. |
| Your plugin ships | One `strings` object, written with your own `__()` and your text domain. |
| Wiring | Wrap each React root in `<StringsProvider strings={ strings }>`. |
| Missing provider | Components that need a string throw. There is no English fallback. |

## Why

WordPress translates a plugin's JavaScript per script handle and per text
domain: `wp_set_script_translations( 'my-plugin-admin', 'my-plugin' )` loads the
JSON for *your* bundle under *your* domain. A `__( 'Cancel', 'vip-admin-ui' )`
compiled into your bundle from this package would look up a domain nobody loads,
and `wp i18n make-pot` would not extract it into your POT either. It would ship
in English to every locale, silently.

So every word these components put on screen comes from you. Most of them
already arrive as props (`label`, `removeLabel`, `emptyLabel`, `noneLabel`,
`countLabel`…). The few that a component needs on its own — the default buttons
of `useConfirm`, the collapse toggle's name, the accessible names on a field
list's rows — come from the provider.

A missing provider throws rather than falling back to English, for the same
reason: a fallback would hide the omission until a translator filed a bug.

## The template

Copy this into your plugin, change the text domain, and keep the keys exactly as
they are. Keys that take arguments are functions, so `sprintf` and the
translator comments stay in your code, where `make-pot` can read them.

```js
// src/vip-admin-ui-strings.js
import { __, sprintf } from '@wordpress/i18n';

export const strings = {
	// useConfirm: the default title and confirm button, and the cancel button.
	confirm: __( 'Confirm', 'my-plugin' ),
	cancel: __( 'Cancel', 'my-plugin' ),

	// SettingsLoading, when no `label` is passed.
	loading: __( 'Loading…', 'my-plugin' ),

	// InspectorShell's collapse toggle.
	expandPanel: __( 'Expand panel', 'my-plugin' ),
	collapsePanel: __( 'Collapse panel', 'my-plugin' ),

	// InspectorFieldList: a row whose storage key would be refused on save.
	// The short form replaces the row's value; the full form is handed to
	// `renderConfig` as `problem.full`, for the key field's help text.
	needsKey: __( 'Needs a key', 'my-plugin' ),
	keyRequired: __( 'A key is required.', 'my-plugin' ),
	duplicateKey: __( 'Duplicate key', 'my-plugin' ),
	duplicateKeyDetail: __( 'Another field already uses this key.', 'my-plugin' ),

	// InspectorFieldList: accessible names for a row's button and drag handle.
	configureItem: ( name ) =>
		/* translators: %s: the item's name. */
		sprintf( __( 'Configure %s', 'my-plugin' ), name ),
	selectItem: ( name ) =>
		/* translators: %s: the item's name. */
		sprintf( __( 'Select %s', 'my-plugin' ), name ),
	reorderItem: ( name ) =>
		/* translators: %s: the item's name. */
		sprintf( __( 'Reorder %s', 'my-plugin' ), name ),

	// InspectorChoiceRow: the row's accessible name, which has to say the value.
	settingValue: ( label, value ) =>
		/* translators: 1: the setting's name. 2: what it is currently set to. */
		sprintf( __( '%1$s: %2$s', 'my-plugin' ), label, value ),

	// InfoTip: the trigger's accessible name.
	aboutSetting: ( name ) =>
		/* translators: %s: the setting being explained, e.g. "Post status". */
		sprintf( __( 'About %s', 'my-plugin' ), name ),
};
```

Then, at each React root:

```js
import { createRoot } from '@wordpress/element';
import { StringsProvider } from '@automattic/vip-admin-ui';

import { strings } from './vip-admin-ui-strings';

createRoot( container ).render(
	<StringsProvider strings={ strings }>
		<App />
	</StringsProvider>
);
```

A modal or popover rendered by a component inside that tree is inside the
provider too — React context follows the component tree, not the DOM, so
portals are covered.

## Adding a string to the package

A new key is a breaking change for every plugin: their `strings` object is
suddenly incomplete. Prefer a prop. When a component genuinely needs a string of
its own, add the key here and in `.storybook/strings.js`, and call it out in the
release notes as a required addition.
